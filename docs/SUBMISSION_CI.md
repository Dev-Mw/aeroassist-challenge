# AeroAssist — GitHub CI handoff (no GCP required)

## What is ready

- CI on pushes to `main` and pull requests: Python 3.12, Ruff, 74+ Python tests (count depends on current repo), offline RAG evaluation, Docker build and HTTP smoke in a non-root container.
- CD is manual only, behind `GCP_DEPLOY_ENABLED=true`. Do not configure GCP variables for this submission. No deployment is claimed.
- Public golden set is verified locally by `make evaluate-public` with the service running. CI runs an HTTP smoke check but **does not** run the full golden set; do not claim otherwise.

## Upload from *your* Git Bash to *your* GitHub account

1. Create an empty **private** repository named `aeroassist-challenge` under your account (no README or license autogenerated).
2. In the project root, verify `.env`, `.venv`, credentials and `YOLO/` are not staged. Check `git status --short` and `git remote -v`.
3. If `origin` does not exist, run `git remote add origin https://github.com/YOUR_USER/aeroassist-challenge.git`; if it exists, do **not** overwrite it without checking.
4. `git add .github/workflows/ci.yml .github/workflows/cd.yml docs/CONTAINER_CICD.md docs/DECISIONS.md docs/SUBMISSION_CI.md` and (if uploading the complete local repository for the first time) `git add .`, then inspect `git diff --cached --stat` and `git diff --cached --name-only`.
5. `git commit -m "ci: isolate continuous integration from optional GCP deployment"` then `git push -u origin main`. If branch differs, use the actual branch and ensure `main` gets code before expecting the push trigger.
6. Open the repository's **Actions** tab → workflow `ci` → latest run; ensure `test` and `container` are green. Capture its URL/screenshot.
